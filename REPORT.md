# REPORT — Лабораторна робота № 3

## 1. Тема, номер і варіант
- **Тема:** Спадкування, Інтерфейси й Поліморфізм у Java-проєкті.
- **Предметна область:** Заправка (облік транзакцій пального).
- **Варіант:** 24.
- **ОС:** Windows 11 (розробка у VS Code через Git Bash).

## 2. Мета роботи
Розширити класову модель предметної області: винести спільні властивості до базового абстрактного класу, створити підтипи з різною поведінкою (`PetrolTransaction` та `DieselTransaction`), додати `enum` для категорії, реалізувати `equals`/`hashCode` і обробляти різнорідні об'єкти через спільний тип без операторів розгалуження за типом.

## 3. Стан до і після цієї роботи
- **До (ЛР2):** Транзакція описувалася одним монолітним класом `FuelTransaction`. Тип пального зберігався у вигляді `String`.
- **Після (ЛР3):** Створено ієрархію класів з абстрактним `FuelTransaction` та підтипами `PetrolTransaction` і `DieselTransaction`. Тип пального реалізовано через `enum FuelKind`.

## 4. Базовий тип
Абстрактний клас `FuelTransaction` містить:
- **Спільні поля:** `date`, `column`, `kind`, `liters` (`private final`).
- **Інваріанти:** Перевірка невід'ємності літрів, колонки та непорожності дати через статичні методи валідації (запобігає попередженням SpotBugs `CT_CONSTRUCTOR_THROW`).
- **Абстрактний метод:** `public abstract double calculateCost();`.

## 5. Підтипи
- **`PetrolTransaction`:** Містить поля `pricePerLiter` та `hasLoyaltyCard`. Метод `calculateCost()` надає 2% знижки при `hasLoyaltyCard == true`.
- **`DieselTransaction`:** Містить поля `pricePerLiter` та `isWholesale`. Метод `calculateCost()` надає 5% знижки для замовлень > 100 л у гурт.

## 6. enum
Створено `FuelKind` із константами `PETROL` ("Бензин") та `DIESEL` ("Дизель"). Використовується для текстового подання у звітності.

## 7. equals i hashCode
Перевизначено у `FuelTransaction`. Об'єкти вважаються рівними за рівністю класу, дати, колонки та літрів. Перевірено в юніт-тесті з `HashSet` (додавання двох однакових транзакцій залишає розмір множини рівним 1).

## 8. Поліморфізм
У `FuelController.java` підрахунок вартості виконується через потік спільного типу:
`double totalCost = transactions.stream().mapToDouble(FuelTransaction::calculateCost).sum();`
Код не перевіряє `instanceof` та не використовує `switch`/`if`.

## 9. Тестування
- `subtypesCalculateCostDifferently` — перевіряє різницю вартості підтипів.
- `equalObjectsHaveOneSetEntry` — перевіряє `HashSet` і `equals`/`hashCode`.
- `subtypeRejectsInvalidSpecificValue` — відхилення від'ємної ціни.
- `factoryRejectsInvalidFormat` — відхилення невідомих типів.

- `mvnw verify` — 0 помилок у SpotBugs.

## 14. Відповіді на контрольні питання
1. **Поліморфізм** дозволяє викликати метод `calculateCost()` для базового типу, а JVM сама обирає реалізацію підтипу.
2. **`equals`/`hashCode`** потрібні для коректної роботи об'єктів у колекціях типу `HashSet` та `HashMap`.
